# Data Room — Persona-Specific Implementation Plan

_Generated 2026-08-14. A researched, buildable plan for a data room that presents the **right document taxonomy to each persona** — founder, VC/GP, and LP — grounded in the standard industry frameworks each persona actually works from._

---

## 1. Why persona-specific taxonomies

A "data room" is not one thing. Each persona uses a different, well-established document taxonomy:

| Persona | Data room = | Framework it's modeled on |
|---|---|---|
| **Founder** | The **fundraising diligence room** they share with investors | Standard VC due-diligence checklist (NVCA model legal docs, YC/Series-A DD lists) |
| **VC / GP** | The **LP-facing fund data room** they operate | ILPA reporting standards + fund formation docs (LPA/PPM), SEC Reg S-P |
| **LP** | A **scoped read** of the GP's fund room (their own docs + fund-wide docs) | Same as GP, entitlement-filtered |

The founder room is a **distinct taxonomy**. The LP room is a **filtered projection of the GP room** — not a separate corpus. This single insight drives the whole architecture: we build **two document corpora** (founder raise room + fund room) and **three views** (founder, GP-admin, LP-scoped).

But only **8 flat categories** (`subscription, quarterly_letter, capital_call, distribution, k1, financials, policy, other`) and no sub-foldering. LP portal view + view-tracking already shipped.

## 3. Researched taxonomy — Founder raise data room

The canonical VC diligence checklist. Twelve sections; each becomes a top-level folder with a completeness indicator (LPs/investors judge a raise partly on data-room completeness).

| # | Section | Key documents |
|---|---|---|
| 1 | **Corporate & Formation** | Certificate of incorporation, bylaws, board consents & minutes, stockholder agreements, org chart, good-standing certificates |
| 2 | **Capitalization** | Cap table, option pool/ESOP, SAFEs & convertible notes, warrants, **409A valuation**, stock purchase & vesting agreements |
| 3 | **Financials** | Historical P&L / balance sheet / cash flow, **financial model & projections**, budget, bank statements, AR/AP aging |
| 4 | **Metrics & Traction** | KPI dashboard, MRR/ARR, cohort & retention, unit economics (CAC/LTV), sales pipeline |
| 5 | **Product & Technology** | Roadmap, architecture overview, security & pen-test, data-privacy (GDPR/DPA), tech-stack summary |
| 6 | **Intellectual Property** | Patents, trademarks, **IP assignment agreements**, open-source usage, domains |
| 7 | **Legal & Compliance** | Material contracts, customer/vendor agreements, NDAs, litigation history, insurance, licenses/regulatory |
| 8 | **Team & HR** | Org chart, key employee & founder agreements, offer letters, employee census, contractor agreements, benefits |
| 9 | **Market & Strategy** | Market sizing (TAM/SAM/SOM), competitive analysis, GTM strategy |
| 10 | **Customers & Sales** | Customer list, references, case studies, churn analysis, MSAs |
| 11 | **Fundraising** | **Pitch deck**, executive summary, investment teaser, prior-round docs, use of funds, current term sheet |
| 12 | **Tax** | Tax returns, R&D credits, key elections (83(b), QSBS) |

**Access model:** founder owns; grants **per-investor, time-boxed, watermarked, view-tracked** access (reuses the deck-view tracking shipped in P2). Investors see a read-only room; the founder sees who opened what.

## 4. Researched taxonomy — VC/GP fund data room (LP-facing)

ILPA-informed. Nine sections. Documents are either **fund-wide** (`fund_lp_id IS NULL`, every LP sees) or **LP-specific** (`fund_lp_id = X`, only that LP).

| # | Section | Scope | Key documents |
|---|---|---|---|
| 1 | **Fund Formation & Governance** | fund-wide + LP | **LPA**, **PPM**, subscription agreement (LP), **side letters** (LP), GP/management-company docs |
| 2 | **Capital Account** | LP | Capital account statements, commitment schedule |
| 3 | **Capital Calls** | LP | Call notices, wire instructions _(auto-generated by the capital-call wizard)_ |
| 4 | **Distributions** | LP | Distribution notices, waterfall calc _(auto-generated by the distribution wizard)_ |
| 5 | **Financial Reporting** | fund-wide | Quarterly & annual reports, **audited financial statements**, ILPA templates, NAV statements |
| 6 | **Tax** | LP | **K-1s**, tax estimates, foreign-tax docs |
| 7 | **Portfolio** | fund-wide | Portfolio-company summaries, valuations (mark/409A), co-investment docs |
| 8 | **Compliance & Legal** | fund-wide | Form ADV, compliance manual, AML/KYC, **privacy notice (Reg S-P)**, ESG reports |
| 9 | **Investor Relations** | fund-wide | Annual-meeting materials, LP updates, newsletters |

**Auto-population:** categories 3 & 4 are already produced by the capital-call / distribution wizards — their generated PDFs should land here automatically as `capital_call` / `distribution` LP-scoped documents.

## 5. Researched taxonomy — LP view (scoped projection)

The LP sees a **filtered view of §4**, not a new corpus:
- **Their own** LP-scoped docs (subscription, side letter, capital-account statements, call notices, distribution notices, K-1s).
- **Fund-wide** docs (reports, audited financials, compliance/ESG, IR materials).
- Never other LPs' docs.

This is already the model in `getDocumentForLp` / `listDocumentsForLp`; it just needs the richer category set and the section grouping.

## 6. Proposed data model

Extend `data_room_documents` — additive, backward-compatible:

```sql
ALTER TABLE data_room_documents
  ADD COLUMN IF NOT EXISTS room_type   text NOT NULL DEFAULT 'fund'   -- 'fund' | 'founder'
    CHECK (room_type IN ('fund','founder')),
  ADD COLUMN IF NOT EXISTS section     text,     -- top-level taxonomy section (see §3/§4)
  ADD COLUMN IF NOT EXISTS company_id  text,     -- founder room: which company/workspace owns it
  ADD COLUMN IF NOT EXISTS is_required boolean NOT NULL DEFAULT false;  -- drives completeness %
```

- The existing `category` enum stays for fund docs (maps to §4 sections); add a **founder category set** (§3).
- **Investor access** (founder room) — a new grants table:

```sql
CREATE TABLE data_room_access_grants (
  id text PRIMARY KEY DEFAULT gen_random_uuid()::text,
  company_id  text NOT NULL,
  grantee_email text NOT NULL,
  scope text NOT NULL DEFAULT 'all',   -- 'all' | section list (future)
  expires_at timestamptz,
  watermark boolean NOT NULL DEFAULT true,
  created_by text, created_at timestamptz DEFAULT now(),
  revoked_at timestamptz
);
```

- **Taxonomy as data**, not hardcoded — a `lib/dataroom/taxonomy.ts` exporting `FOUNDER_SECTIONS` and `FUND_SECTIONS` (section → label → categories → required?), so the UI and completeness scoring are driven by one source of truth.

## 7. Access & entitlement matrix

| Room | Founder | VC/GP (owner) | VC (other) | LP | Granted investor |
|---|:--:|:--:|:--:|:--:|:--:|
| Founder raise room | ✅ owner (RW) | — | — | — | 👁 read, time-boxed, watermarked, tracked |
| Fund room (admin) | — | ✅ RW | ✅ RW (same firm) | scoped read | — |
| LP scoped view | — | — | — | ✅ own + fund-wide | — |

- Fund-room admin stays behind `requireAdmin` + the VC persona guard.
- LP view stays behind the LP email→`fund_lps` entitlement (already built).
- Founder-room investor access is the **grants** table + a tokenized link (reuse `/portal/[token]` pattern or a new `/room/[token]`).

## 8. UX plan

- **Section-grouped room** (all three views): collapsible sections from the taxonomy, each with a **completeness meter** (`filled required / total required`) and file count. Replaces the flat list + the mock founder folders.
- **Founder room:** "Share room" action → create a grant (email + expiry) → copyable link; an **Investor activity** panel (who viewed what — reuses the shipped `document-engagement-panel`). A **completeness score** header ("Your raise room is 78% complete — add a 409A and IP assignments").
- **GP room:** section grouping + the auto-populated call/distribution notices + the engagement panel (already shipped).
- **LP room:** the section grouping applied to `/lp/documents` (currently a flat list).

## 9. Phased roadmap

**Phase 1 — Taxonomy foundation (no schema risk)**
- `lib/dataroom/taxonomy.ts` (FOUNDER_SECTIONS, FUND_SECTIONS, required flags).
- Migration: `room_type`, `section`, `company_id`, `is_required` (additive).
- Backfill existing fund docs' `section` from their `category`.

**Phase 2 — Fund room upgrade (VC + LP)**
- Group GP data room + `/lp/documents` by section; add completeness meters.
- Auto-file capital-call / distribution wizard PDFs into the room as LP-scoped docs.

**Phase 3 — Founder raise room**
- Replace the mock `data-room-content.tsx` with the real section-grouped room over `data_room_documents` (`room_type='founder'`, scoped by `company_id`).
- Completeness score header; upload into sections.

**Phase 4 — Investor sharing & tracking**
- `data_room_access_grants` + `/room/[token]` read-only investor view (watermarked).
- "Share room" flow + Investor-activity panel (reuse view-tracking).

**Phase 5 — Templates & automation**
- Per-section **required-document checklists** (the §3/§4 lists) shown as "missing" placeholders.
- Optional: request-a-document threads (GP↔LP, founder↔investor).

## 11. Decisions (resolved — industry standard)

1. **Founder-room ownership = per `company_id`.** Data rooms are per-entity across the industry (DocSend, Ansarada, Carta). A founder with multiple entities gets one room per entity. `data_room_documents.company_id` scopes the founder corpus.
2. **Investor access = tokenized magic-link, no account.** Email-gated, **watermarked**, **expiring**, **view-tracked** — the DocSend/Digify norm for founder rooms; requiring a login kills investor conversion. Implemented via `data_room_access_grants` + `/room/[token]`.
3. **Completeness = guidance, never a gate.** No data-room tool blocks sharing; founders deliberately share incomplete rooms early. Show a completeness score + missing-doc nudges and a **soft warning** below a threshold (default 60%), but always allow "Share".
4. **Persist `section` explicitly; keep `category`.** Real data rooms are section/folder hierarchies, so `section` is the primary taxonomy field. `category` is retained for the auto-generated notice docs (`capital_call` / `distribution`) and legacy fund rows; `section` is backfilled from `category` for existing docs.

**Defaults locked in:** grant expiry default **14 days**, watermark **on**, completeness warning threshold **60%**, founder room keyed by `company_id`, fund room keyed by `fund_id` (unchanged).
