# Anker — Complete Auth + Onboarding Integration Guide

## Files in this package

| File | What it does |
|------|-------------|
| `client/src/hooks/use-auth.ts` | Auth state hook — wraps TanStack Query, exposes login/signup/logout + OAuth helpers |
| `client/src/pages/AuthPage.tsx` | Unified sign-in / sign-up page with Google, GitHub, LinkedIn + email/password |
| `client/src/pages/OnboardingPage.tsx` | 6-step (founder) / 5-step (investor) onboarding that populates every platform entity |
| `client/src/App.tsx` | Routing patch — adds /auth, /onboarding, route guards |
| `server/auth-routes.ts` | Passport strategies for all 4 providers, signup, login, logout endpoints |
| `server/onboarding-routes.ts` | Writes to startups, investors, investmentFirms, dealRooms, checklistSessions |
| `shared/schema-additions.ts` | Schema columns + SQL migration + Drizzle snippets |

---

## Step 1 — Install missing dependencies

All Passport + bcrypt packages are already in `package.json`. Only the OAuth strategy adapters need adding:

```bash
npm install passport-google-oauth20 passport-github2 passport-linkedin-oauth2
npm install -D @types/passport-google-oauth20 @types/passport-github2
```

---

## Step 2 — Add environment variables

Add to your Replit Secrets (or `.env`):

```env
# Google — console.cloud.google.com/apis/credentials
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

# GitHub — github.com/settings/developers → OAuth Apps
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=

# LinkedIn — developer.linkedin.com/apps
LINKEDIN_CLIENT_ID=
LINKEDIN_CLIENT_SECRET=

# Your deployed URL
APP_URL=https://your-app.replit.app
```

**OAuth callback URLs to register with each provider:**
- Google: `{APP_URL}/api/auth/google/callback`
- GitHub: `{APP_URL}/api/auth/github/callback`
- LinkedIn: `{APP_URL}/api/auth/linkedin/callback`

## Step 4 — Wire routes in server/routes.ts

Add near the top of your existing `server/routes.ts`, **before** any other route registrations:

```typescript
import authRoutes from "./auth-routes.js";
import onboardingRoutes from "./onboarding-routes.js";

// Auth
app.use("/api/auth", authRoutes);

// Onboarding
app.use("/api/onboarding", onboardingRoutes);
```

## Step 6 — Update client/src/App.tsx

Replace or merge your existing App.tsx with the routing patch. The key changes:

```typescript
// 1. Import the new hook and pages
import { useAuth } from "./hooks/use-auth";
import AuthPage from "./pages/AuthPage";
import OnboardingPage from "./pages/OnboardingPage";

// 2. Add the three guard components (ProtectedRoute, OnboardingGuard, GuestOnlyRoute)
//    — copy from App.tsx in this package

// 3. Add these routes inside your <Switch>:
<Route path="/auth">
  <GuestOnlyRoute><AuthPage /></GuestOnlyRoute>
</Route>

<Route path="/onboarding">
  <ProtectedRoute><OnboardingPage /></ProtectedRoute>
</Route>

// 4. Wrap existing /app/* route:
<Route path="/app/:rest*">
  <ProtectedRoute>
    <OnboardingGuard>
      <AppLayout>...</AppLayout>
    </OnboardingGuard>
  </ProtectedRoute>
</Route>
```

---

## Step 7 — Replace useAuth usage in existing components

The existing code may call `useQuery(["/api/auth/user"])` directly. Replace with the hook:

```typescript
// Before (existing pattern)
const { data: user } = useQuery({ queryKey: ["/api/auth/user"] });

// After (new hook — backward compatible)
const { user, isAuthenticated, isFounder, isInvestor, isAdmin } = useAuth();
```

The hook still uses `/api/auth/user` under the hood so existing API responses will work.

---

## Step 8 — Update AppLayout.tsx nav guards

AppLayout uses `userType` to show founder vs investor navigation. The new schema writes `userType` as `"founder"` or `"investor"` — the same field it already reads. No change needed if AppLayout already checks `user.userType`.

## What the matchmaking engine reads from onboarding data

From `replit.md` — the matchmaking algorithm weighs these factors:

| Factor | Weight | Onboarding field |
|--------|--------|-----------------|
| Industry alignment | 30% | `startups.industry` + `investors.preferredSectors` |
| Stage compatibility | 25% | `startups.stage` + `investors.preferredStages` |
| Geographic fit | 20% | `startups.targetGeographies` + `investors.geographyFocus` |
| Check size alignment | 15% | `startups.fundingTarget` + `investors.typicalCheckSize` |
| Investor type | 10% | `startups.preferredInvestorTypes` + `investors` classification |

**Niche boost** — `startups.nicheIndustry` + `investors.focusNiches`:
- `"film"` → activates 25+ film/slate-financing keyword scoring
- `"realestate"` → activates 30+ RE keyword scoring  
- `"sports"` → activates sports-tech, esports keyword scoring

The pitch deck URL, once set, queues the AI pitch deck analysis pipeline (MBB-style report with stage-specific frameworks).
