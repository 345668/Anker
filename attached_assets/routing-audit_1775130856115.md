# Anker — Routing & UX Audit + Restructure

## Problems identified in the current navigation

### 1. The matching workflow is split across four separate pages

A founder trying to raise capital must currently navigate through:

```
/app/fundraising      → Overview (FundManagement.tsx) — has a "Open Forecasting Studio" CTA
/app/my-startup       → Set company profile (prerequisite for matching)
/app/matching         → Run matches, see results
/app/matching-logs    → See history of past runs
```

These are four separate nav entries for a single linear workflow. A new user has no idea that they must complete `/app/my-startup` before matching works, and there is no guided handoff between pages.

### 2. Investors and Investment Firms are duplicate nav entries

```
/app/investors          Individual investor contacts (John Smith, Partner @ XYZ)
/app/investment-firms   Firm-level records (XYZ Ventures, $500M AUM)
```

These describe the same entity at two levels of granularity. In the current nav they appear as two separate items, which forces users to context-switch between them without understanding the relationship. The matching engine returns results at the investor level but needs firm data to score them — yet the user sees them completely separately.

### 3. Matching Logs has no reason to be a standalone nav item

`/app/matching-logs` is a history view of past match runs. It only makes sense in the context of the matching page. As a standalone nav item it confuses users who don't know what a "matching log" is and creates a second entry point into matching history that duplicates the session list already visible on the matching page.

### 4. The fundraising pipeline has no visible progression

Nothing in the UI communicates that the workflow is: profile → run matches → track → close. Each page is a dead end — completing an action on one page does not surface the next logical step.

### 5. Checklist pages are isolated from the deal flow

Three checklist pages (`/app/dd-checklist`, `/app/data-room-checklist`, `/app/eoy-review`) exist as standalone nav items. They are most useful when contextually attached to an active deal or matching session, but are currently unreachable from those flows.

## Restructured information architecture

### Before

```
Sidebar nav (founder):
├── Dashboard
├── My Startup            ← profile setup buried in nav
├── Fundraising           ← vague label
├── Investors             ← both levels of same entity
├── Investment Firms      ← redundant with above
├── Matching              ← isolated
├── Matching Logs         ← should not be a nav item
├── Deal Rooms
├── DD Checklist          ← isolated from deal flow
├── Data Room Checklist   ← isolated from deal flow  
├── EOY Review            ← isolated from deal flow
├── Financial Tools
├── Forecasting Studio
└── News
```

### After

```
Sidebar nav (founder):
├── Dashboard
├── Fundraise             ← replaces Fundraising + Matching + MatchingLogs
│   (tabbed: Profile → Find Investors → My Matches → Deal Rooms)
├── Investor Database     ← replaces Investors + Investment Firms (unified)
├── Due Diligence         ← replaces DD Checklist + Data Room Checklist + EOY Review
├── Financial Tools       ← replaces Tools + Forecasting (tabbed internally)
└── News
```

## Page consolidations

### Consolidation 1: `/app/fundraise` — FundraisingHub

Absorbs and replaces: `FundManagement`, `Matching`, `MatchingLogs`, partially `MyStartup`

Tab structure:
1. **Profile** — startup profile completeness, editable inline, match readiness score
2. **Find Investors** — run matches, choose algorithm, view results
3. **My Matches** — tracked matches with status pipeline (replaces MatchingLogs)
4. **Deal Rooms** — link to active deal rooms created from matches

Routing: `/app/fundraise` (replaces `/app/fundraising`, `/app/matching`, `/app/matching-logs`)
Deep links: `/app/fundraise?tab=matches&session=:id`

### Consolidation 2: `/app/investors` — InvestorDatabase

Absorbs and replaces: `Investors`, `InvestmentFirms`

Tab structure:
1. **Firms** — investment firm cards with Deep Research enrichment
2. **Contacts** — individual investor contacts, Folk CRM sync

The two levels are shown as tabs of the same concept, not separate pages.

### Consolidation 3: `/app/due-diligence` — DueDiligence

Absorbs and replaces: `DDChecklist`, `DataRoomChecklist`, `EOYReview`

Tab structure:
1. **Readiness** — DD diagnostic (17 weighted questions)
2. **Full Checklist** — 39-item early stage DD checklist
3. **Data Room** — fund data room checklist (EM vs Fund II+)
4. **Year-End Review** — EOY fund health review

### Consolidation 4: `/app/tools` — ToolsHub (already planned but split)

Absorbs: `FinancialTools`, `ForecastingStudio`

Tab structure:
1. **Calculators** — 11 reactive calculators (existing)
2. **Forecasting** — 9 revenue/fund models (existing)

## The Fundraise flow — linear progression design

The key design principle: each tab in FundraisingHub shows a "next step" CTA that moves the user forward. Profile completeness gates the Find Investors tab. Running matches populates the My Matches tab. Advancing a match to a deal opens Deal Rooms.

```
/app/fundraise
│
├── Tab 1: Profile
│   ├── Startup profile fields (inline editable)
│   ├── Match readiness score (0–100, progress bar)
│   ├── Missing fields highlighted as blockers
│   └── CTA: "Profile complete — Find investors →" (unlocks Tab 2)
│
├── Tab 2: Find Investors
│   ├── Algorithm selector (Standard / Accelerated / Niche / Custom weights)
│   ├── One "Run matches" button
│   ├── Live progress indicator during run
│   ├── Results grouped by tier (Champion / A / B / C)
│   ├── Per-card: expand score breakdown, set status, add to CRM
│   └── CTA: "Track these matches →" (moves to Tab 3)
│
├── Tab 3: My Matches
│   ├── All sessions listed (most recent first)
│   ├── Status pipeline: Pending → In CRM → Contacted → Responded → Won/Lost
│   ├── Filter by tier, status, session date
│   ├── Bulk actions: add to CRM, send to outreach sequence, mark passed
│   └── CTA: "Open deal room" (per match, moves to Tab 4)
│
└── Tab 4: Deal Rooms
    ├── Active deal rooms linked to matches
    ├── Document upload, milestones, notes
    └── CTA: "Run a new match" (loops back to Tab 2)
```

## Route map (complete restructure)

### Routes to KEEP (unchanged)
- `/app/dashboard` — unchanged
- `/app/news` — unchanged
- `/app/settings` — unchanged
- `/admin/*` — all admin routes unchanged
- `/onboarding` — from previous session

### Routes to CREATE
- `/app/fundraise` — new FundraisingHub (tabbed)
- `/app/investors` — new InvestorDatabase (tabbed, replaces both)
- `/app/due-diligence` — new DueDiligence (tabbed)
- `/app/tools` — updated ToolsHub (tabs for calculators + forecasting)

### Routes to DELETE / REDIRECT
| Old route | Redirect to | Reason |
|-----------|-------------|--------|
| `/app/fundraising` | `/app/fundraise` | Renamed + absorbed |
| `/app/matching` | `/app/fundraise?tab=find` | Absorbed into FundraisingHub |
| `/app/matching-logs` | `/app/fundraise?tab=matches` | Not a standalone page |
| `/app/my-startup` | `/app/fundraise?tab=profile` | Part of fundraise flow |
| `/app/investment-firms` | `/app/investors?tab=firms` | Tab of InvestorDatabase |
| `/app/dd-checklist` | `/app/due-diligence?tab=checklist` | Tab of DueDiligence |
| `/app/data-room-checklist` | `/app/due-diligence?tab=data-room` | Tab of DueDiligence |
| `/app/eoy-review` | `/app/due-diligence?tab=eoy` | Tab of DueDiligence |
| `/app/deal-rooms` | `/app/fundraise?tab=deals` | Tab of FundraisingHub |
